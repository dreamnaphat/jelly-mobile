> เอกสารนี้บอกว่า **จะทำอะไร เมื่อไร และตัดสินใจอะไรบ้าง** ส่วนรายละเอียดว่าระบบต้องเป็นอย่างไรอยู่ใน [SPEC.md](SPEC.md)
> สถานะ: **ยังไม่เริ่ม** · อัปเดต 27 ก.ย. 2026

## 1. ภาพรวม

| Phase | งาน | เวลา | สถานะ |
|---|---|---|---|
| 0 | ทดสอบความเป็นไปได้บนเครื่องจริง | 1–2 สัปดาห์ | ยังไม่เริ่ม |
| 1 | แอป Android เวอร์ชันแรก | 3–4 สัปดาห์ | ยังไม่เริ่ม |

## 3. รายละเอียดแต่ละ Phase

### Phase 0: ทดสอบความเป็นไปได้ (1–2 สัปดาห์)

**งาน**
- [ ] อัดประโยคทดสอบไทย ~50 และจีน ~50 จากสถานการณ์จริง (ซื้อขาย ถามทาง ร้านอาหาร) ทั้งในที่เงียบและที่เสียงดัง
- [ ] ทำแอปทดสอบ Android ที่วัดเวลาแต่ละขั้นได้
- [ ] เทียบโมเดลฟังภาษาไทย: Typhoon ASR, Zipformer ภาษาไทย และใช้ Azure STT เป็นเกณฑ์
- [ ] ทดสอบโมเดลฟังและพูดภาษาจีนใน sherpa-onnx
- [ ] ทำตัวกลางบน Cloudflare Workers ที่เรียก Azure Translator และ Azure TTS
- [ ] วัดเวลารวมตลอดระบบบน 4G ในไทย

**ผ่านเมื่อ**
- เวลารวมได้ตามเป้า N2 ใน SPEC (p90 ≤ 1.5 วิ)
- การฟังภาษาไทยในเครื่องแม่นพอใช้ ถ้าไม่พอ ให้ใช้ Azure STT F0 เป็นโหมดแม่นยำสูง

### Phase 1: แอป Android เวอร์ชันแรก (3–4 สัปดาห์)

- [ ] โครงแอป Kotlin + Jetpack Compose โดยไม่พึ่ง Google services
- [ ] ระบบดาวน์โหลดโมเดลตอนเปิดแอปครั้งแรก
- [ ] ต่อระบบฟัง → แปล → พูด ครบทั้งสองทิศทาง (F1, F2)
- [ ] ปุ่มกดพูด 2 ภาษา ข้อความขึ้นสด และหน้าจอสำหรับนั่งหันหน้าคุยกัน (F3–F5)
- [ ] ประวัติการสนทนาและปุ่มเล่นซ้ำ (F6)
- [ ] ทดสอบบน Android ทั่วไปและ Huawei EMUI

### Phase 2: เร่งความเร็วและทดลองใช้จริง (2–3 สัปดาห์)

- [ ] เริ่มเล่นเสียงทันทีที่ได้ท่อนแรก, โหลดโมเดลค้างไว้, เปิดการเชื่อมต่อค้างไว้
- [ ] ปิดไมค์ระหว่างเล่นเสียงคำแปล
- [ ] ตั้งค่าครับ/ค่ะ จีนตัวย่อ/ตัวเต็ม และรายการคำเฉพาะ (F7)
- [ ] แก้ข้อความแล้วแปลใหม่ (F6)
- [ ] ลองคุยกับคนจีนจริง แล้วเก็บประโยคที่แปลผิดมาแก้
- [ ] วัดผลตาม N2 และ N4 ใน SPEC

### Phase 3: แอป HarmonyOS (3–4 สัปดาห์)

- [ ] โครงแอป ArkTS + ArkUI บน DevEco Studio
- [ ] ฝั่งภาษาจีนใช้ Core Speech Kit ส่วนฝั่งภาษาไทยใช้ sherpa-onnx
- [ ] ใช้ตัวกลางบนคลาวด์ตัวเดิม
- [ ] ทดสอบบน emulator หรือเครื่องจริง

### Phase 4: โหมดออฟไลน์ (2–3 สัปดาห์)

- [ ] แปลในเครื่องด้วย HY-MT1.5-1.8B ผ่าน llama.cpp (Android ก่อน)
- [ ] พูดภาษาไทยในเครื่องด้วย MMS-TTS Thai
- [ ] สลับโหมดอัตโนมัติเมื่อไม่มีเน็ตหรือโควตาหมด (F8)

## 4. การซื้อมือถือ (งบเครื่องละ 40,000 บาท)

สเปกที่ต้องการอยู่ใน SPEC ข้อ 7 รุ่นที่แนะนำ (ราคาไทย ณ ก.ย. 2026):

| ฝั่ง | รุ่นแนะนำ | ชิป / RAM / ความจุ | ราคา |
|---|---|---|---|
| Android | **Xiaomi 17** | Snapdragon 8 Elite Gen 5 / 12 GB / 512 GB | 32,990 บาท |
| Android (ตัวเลือกรอง) | vivo X300 Pro | Dimensity 9500 / 16 GB / 512 GB | 39,999 บาท |
| Huawei | **Huawei Pura 80 Pro** | Kirin 9020 / 12 GB / 512 GB (EMUI 15) | 38,990 บาท |

- Pura 80 Pro ที่ขายในไทยใช้ EMUI จึงรันแอป Android ได้ แต่ทดสอบแอป HarmonyOS ไม่ได้ ให้ใช้ emulator ของ DevEco Studio แทน
- ราคาในไทยเปลี่ยนเร็ว ต้องเช็กราคาและโปรโมชันก่อนซื้อ

## 5. ความเสี่ยงของโปรเจกต์

| ความเสี่ยง | ผลกระทบ | ทางแก้ |
|---|---|---|
| การฟังภาษาไทยในเครื่องแม่นไม่พอในที่เสียงดัง | คำแปลผิด | ใช้ Azure STT F0 (5 ชม./เดือน) เป็นโหมดแม่นยำสูง |
| โควตาฟรีไม่พอเมื่อมีผู้ใช้เยอะ | บริการหยุดตอบ | สลับไปโหมดออฟไลน์ หรือจำกัดผู้ใช้ |
| เงื่อนไขระดับฟรีเปลี่ยน | อาจต้องมีค่าใช้จ่าย | มีโหมดออฟไลน์ไว้เสมอ ออกแบบให้เปลี่ยนผู้ให้บริการได้ |
| เน็ตอ่อน | เกินเป้าเวลา | แสดงข้อความก่อนเสียง และมีโหมดออฟไลน์ |
| ใช้ในจีนแผ่นดินใหญ่ด้วยซิมหรือ Wi-Fi จีน | อาจเข้าบริการคลาวด์ไม่ได้ | ทดสอบก่อนเดินทาง และใช้โหมดออฟไลน์ |
| MMS-TTS Thai ห้ามใช้เชิงพาณิชย์ | ขายแอปไม่ได้ถ้ายังใช้โมเดลนี้ | ถ้าจะขาย ต้องหาหรือเทรนเสียงไทยเอง |
